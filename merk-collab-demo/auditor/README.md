# Merk Collaborative Editor - Auditor Tool

A standalone tool to verify the integrity of the Merk collaborative editor changelog.

## What It Does

The auditor reads the changelog file generated by the server and:

1. **Verifies each Merkle proof** against the previous root hash
2. **Tracks root hash evolution** through all operations
3. **Detects tampering** or corruption in the server's tree
4. **Reports statistics** on operations and verification results

## Why This Matters

- **Independent verification**: Auditor runs separately from the server
- **Tamper detection**: Catches if server modified the tree incorrectly
- **Compliance**: Provides audit trail for regulatory requirements
- **Trust model**: Clients trust server ordering, auditors verify integrity

## Usage

### Basic Audit

```bash
# Get the changelog path from the server output
# Server prints: "Changelog location: /tmp/.tmpXXXXXX/changelog.jsonl"

# Run the auditor
cargo run --release -- /tmp/.tmpXXXXXX/changelog.jsonl
```

### Verbose Mode

See each operation as it's verified:

```bash
cargo run --release -- /tmp/.tmpXXXXXX/changelog.jsonl --verbose
```

### Stop on First Error

Exit immediately if any proof fails:

```bash
cargo run --release -- /tmp/.tmpXXXXXX/changelog.jsonl --stop-on-error
```

## How It Works

### Proof Verification Flow

1. Read changelog entry: `{op_index, operation, uuid, proof, new_root_hash}`
2. Decode proof from base64
3. Deserialize using bincode
4. Call `verify_positional_proof()` with:
   - Previous root hash (from last verified operation)
   - Position and UUID from entry
   - Value (for inserts)
5. If verification succeeds, update current root hash
6. Continue to next operation

### Root Hash Chain

```
Operation 0:  (initial) → [proof] → root_0
Operation 1:  root_0    → [proof] → root_1
Operation 2:  root_1    → [proof] → root_2
...
```

Each proof must be valid against the previous root hash, forming a chain of trust.

## Integration with Demo

### Running the Full Stack

**Terminal 1 - Server:**
```bash
cd merk-collab-demo/server
cargo run --release
# Note the changelog path from output
```

**Terminal 2 - Client:**
```bash
cd merk-collab-demo/client
npm run dev
# Open http://localhost:5173 and type some text
```

**Terminal 3 - Auditor:**
```bash
cd merk-collab-demo/auditor
cargo run --release -- /tmp/.tmpXXXXXX/changelog.jsonl
```

### Real-Time Auditing

Watch the changelog and verify as operations arrive:

```bash
# In one terminal, tail the changelog
tail -f /tmp/.tmpXXXXXX/changelog.jsonl

# In another, periodically run the auditor
while true; do 
    cargo run --release -- /tmp/.tmpXXXXXX/changelog.jsonl
    sleep 5
done
```

## Exit Codes

- `0` - All proofs verified successfully
- `1` - One or more proofs failed verification
- `1` - File not found or parsing error

## Dependencies

- `grovedb-merk` - For `verify_positional_proof()` function
- `serde`/`serde_json` - For parsing changelog entries
- `base64` - For decoding proofs
- `clap` - For command-line parsing
- `colored` - For pretty output

In a production system:

1. **Archive changelogs**: Rotate and compress old logs
2. **Scheduled audits**: Run auditor periodically via cron
3. **Alert on failures**: Send notifications if proofs fail
4. **Store audit results**: Keep history of verification runs
5. **Compare with backups**: Cross-check against separate storage

## Architecture

```
┌─────────────────────────────────────────────────────────────┐
│                    Server (Authoritative)                    │
│  - Applies operations to Merk tree                           │
│  - Generates proofs for each operation                       │
│  - Writes to changelog: [op, proof, new_root]                │
└─────────────────────────────────────────────────────────────┘
                            ↓
                    changelog.jsonl
                            ↓
┌─────────────────────────────────────────────────────────────┐
│                    Auditor (Independent)                     │
│  - Reads changelog offline                                   │
│  - Verifies each proof cryptographically                     │
│  - Detects any tampering or corruption                       │
│  - Reports verification results                              │
└─────────────────────────────────────────────────────────────┘
```

The auditor has **no connection to the server** - it operates entirely on the changelog file, providing truly independent verification.
